# Module: `auth` (Phase 1)

Registration, login (JWT), and the current-user endpoint. Owns the `User` entity and is the
source of identity/roles for the whole system. JWT infrastructure itself lives in `common/security`
(see [common.md](common.md)) so module dependencies stay one-directional (`auth` → `common`).

## Endpoints (`/api/v1/auth`)

| Method | Path | Access | Purpose |
|---|---|---|---|
| POST | `/register` | 🔓 public | Register a CUSTOMER. Returns `201` + `RegisterResponse`. |
| POST | `/login` | 🔓 public | Verify credentials, return a JWT access token + user summary. |
| GET | `/me` | 👤 authenticated | Return the current principal (`userId`, `email`, `role`). |

`/register` and `/login` are the only permitted auth paths in `SecurityConfig`; `/me` requires a token.

## Layers (`com.moviebooking.ticket_booking.auth`)

| Layer | Class | Notes |
|---|---|---|
| entity | `User` (extends `BaseEntity`), `Role` (ADMIN, CUSTOMER) | Table `users`; `email` unique; `password_hash` BCrypt. |
| repository | `UserRepository` | `findByEmail`, `existsByEmail`. |
| dto | `RegisterRequest`, `RegisterResponse`, `LoginRequest`, `LoginResponse`, `AuthUserSummary`, `CurrentUserResponse` | Validation on requests; **no entity crosses the API boundary**. |
| service | `AuthService` | `register` (creates CUSTOMER, hashes password, rejects duplicate email) and `authenticate` (verifies password). |
| handler | `AuthRequestHandler` | Orchestrates service + `JwtService`, maps entity ↔ DTO, issues tokens. |
| web | `AuthController` | HTTP mapping only; `@Valid` request bodies; delegates to the handler. |
| exception | `InvalidCredentialsException` (401) | Does not reveal whether email or password was wrong. |

## AuthN / AuthZ

- **Token:** stateless HS256 JWT. Claims: `sub`=email, `uid`=userId, `role`=role name.
  Default expiry 24h (`app.jwt.expiration`), signed with `app.jwt.secret` (≥32 bytes).
- **Filter:** `JwtAuthenticationFilter` (in `common`) sets an `AuthenticatedUser` principal with
  authority `ROLE_<role>`. `@AuthenticationPrincipal AuthenticatedUser` is available to controllers.
- **RBAC:** enforced per-endpoint with `@PreAuthorize("hasRole('ADMIN'|'CUSTOMER')")` (method
  security). Denials return `403` Problem Details via `GlobalExceptionHandler`.

## Error responses

| Status | errorCode | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Bad request body (with `errors[]`). |
| 401 | `INVALID_CREDENTIALS` | Wrong email/password at login. |
| 401 | `UNAUTHENTICATED` | Missing/invalid token on a protected route. |
| 403 | `ACCESS_DENIED` | Authenticated but wrong role. |
| 409 | `CONFLICT` | Email already registered. |

## Key decisions

- **JWT infra in `common/security`** (not `auth`) to avoid an inverted `common → auth` dependency;
  overrides DESIGN §3's placement, consistent with §2 ("common owns security config").
- **First ADMIN via Flyway seed** (`V2__create_users.sql`): `admin@moviebooking.com` / `Admin@12345`
  (BCrypt `$2y$`). Rotate after first login in real environments. Public registration creates
  CUSTOMER only.
- `/auth/me` added beyond DESIGN's endpoint list — lightweight "who am I" from the token, no DB hit.

## How to test

- **Automated:** `./gradlew test` —
  `AuthServiceTest` (register/duplicate/authenticate paths, mocked repo),
  `JwtServiceTest` (round-trip, tampered, expired),
  `AuthControllerTest` (status + validation messages, standalone MockMvc),
  `AuthIntegrationTest` (register→login→/me, duplicate `409`, bad login `401`, no-token `401`,
  and **RBAC**: customer `403` / admin `200` on an admin-only route, using the seeded admin).
- **Manual:** `./gradlew bootRun`, then Postman folder *Phase 1 - Auth* (Login saves `{{accessToken}}`
  automatically for `/me`).
